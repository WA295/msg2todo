## 一、项目简介

**iTodo** 是一个面向校园的「消息 → 待办」生活服务平台:QQ 消息自动提取待办,课表 / 番茄钟 / 天气 / 倒计时 / 快递识别 / 留言板一站式管理,支持 **网页 / 安卓 App / 桌面版 / QQ 机器人** 多端。

## 二、技术栈与架构

```
┌────────────┐  反向 WS :3001   ┌──────────────────────────────┐
│ QQ + NapCat│ ───────────────► │  iTodo (Node.js)             │
│ (或学生自建)│                  │  ├─ OneBot v11 服务          │
└────────────┘                  │  ├─ LLM / 本地中文规则提取    │
                                │  ├─ SQLite 存储(按用户隔离)  │
┌────────────┐   HTTP :8080     │  ├─ 看板 / PWA / 安卓 App    │
│ 浏览器/App │ ◄──────────────► │  ├─ SSE 实时推送             │
└────────────┘                  │  └─ 手机推送(Web Push/Bark) │
                                └──────────────────────────────┘
```

- **后端**:Node.js + Express + SQLite(`node:sqlite`)
- **前端**:单文件 `public/index.html`(原生 JS + iOS 设计系统)
- **客户端**:PWA / Capacitor 安卓 App / Electron 桌面版
- **QQ 接入**:OneBot v11 反向 WebSocket(NapCat / LLOneBot / Shamrock)
- **推送**:Web Push(VAPID)+ Bark(iOS)+ PushDeer(安卓)+ QQ 私聊
- **部署**:阿里云 ECS + systemd + Caddy(自动 HTTPS)

**核心管线**(`src/todo.js` 的 `handleIncoming()`):
记录原始消息 → 关键词预过滤 → LLM 提取(失败降级本地规则)→ 判断是否待办 → 写库 → 触发推送 → 可选回复。

## 五、QQ 机器人:双模式架构(最新核心)

iTodo 支持 **两种并存的 QQ 接入模式**:

| 模式 | 谁接收消息 | 待办归属 | 适用 |
|------|-----------|---------|------|
| 🤖 **共享机器人** | 公共号 `2127511079` | 发消息给机器人的同学(按发送者) | 全班通用,零门槛 |
| 👤 **个人机器人** | **学生自己的 QQ 号** | **学生本人**(按自己 QQ 号) | 每个人接收自己的消息 |

### 个人机器人模式(本次新增)
学生自己的 QQ 号连上服务器后,**收到的一切消息**(好友私聊、班群通知)自动提取成**他自己的**待办;自己发的消息也可处理(可给「文件传输助手」发指令),提醒推回自己的 QQ。

- 服务器按 `self_id` 智能识别:已登记学生 → 个人模式;公共号 → 共享模式
- 个人模式下 `chatId = 学生自己的 QQ 号`,所有归属逻辑自动正确
- 公网开放 OneBot 接入(端口 `3001`,令牌 `itodo3001`,**本机回环免令牌**)
- 学生接入:App 绑定 QQ → 装 LLOneBot/NapCat/Shamrock → 反向 WS 填 `ws://182.92.163.6:3001`
- 部署教程见 `docs/个人QQ机器人.md`;设置页有「🤖 个人 QQ 机器人」入口

> **兜底设计**:待办页已对**所有用户开放**,即使 QQ 掉线,同学仍可在 App 内手动添加待办,不受影响。
