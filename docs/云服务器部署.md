# ☁️ 云服务器部署指南

把 iTodo 部署到云服务器后,手机 App **在任何网络(4G/5G/学校 WiFi)都能用**,彻底摆脱"和电脑同网"的限制。

> 本文已按 2026-10 的实际脚本重写。systemd / Caddy 配置不再只写在文档里,而是仓库中的真实文件(`deploy/`)。

## 一、买服务器(5 分钟)

任选一家(都有学生优惠,9.9 元/月左右):

- 阿里云:轻量应用服务器 / ECS 学生机
- 腾讯云:轻量应用服务器 / 学生机
- 京东云 / 华为云:同样有活动价

配置要求:

| 场景 | 建议配置 |
|---|---|
| 只跑 iTodo 主服务 | **1 核 2G 够用**(当前线上就是 1 核 2G) |
| 同时跑 NapCat(公共 QQ 机器人) | **2 核 2G 更稳**(QQNT + xvfb 比较吃内存) |

系统选 **Ubuntu 22.04 或 24.04**。拿到的东西:公网 IP + root 密码(控制台可重置)。

> 🔐 部署完成后请**立刻改成公钥登录并关闭密码登录**(见文末「安全建议」)。

## 二、一键部署(约 5 分钟)

SSH 登录服务器后运行(注意:**`TOKEN` 现在是必填项**,旧版的硬编码默认令牌已随公开仓库泄露,故已移除):

```bash
# 拿到脚本(换成你自己的分支/仓库)
curl -sL https://raw.githubusercontent.com/Miraculy/msg2todo/main/scripts/deploy-cloud.sh -o deploy-cloud.sh

# 国内服务器 GitHub 不通时:
# curl -sL https://ghfast.top/https://raw.githubusercontent.com/Miraculy/msg2todo/main/scripts/deploy-cloud.sh -o deploy-cloud.sh

# 生成一个管理员令牌
TOKEN=$(openssl rand -hex 24)

# 执行部署(有域名就带上 DOMAIN,自动配 HTTPS)
TOKEN=$TOKEN DOMAIN=你的域名.com MIRROR=1 bash deploy-cloud.sh
```

常用环境变量:

| 变量 | 说明 |
|---|---|
| `TOKEN` | **必填**,管理员令牌(看板"管理员登录"用) |
| `DOMAIN` | 填写则自动装 Caddy 并签 HTTPS 证书 |
| `QQ_NUMBER` | 填写才安装 NapCat 公共机器人 |
| `MIRROR=1` | 国内网络:走 npmmirror / ghfast 下载 |
| `NODE_VERSION` | 默认 `22.14.0`,下载会**校验官方 SHA-256** |
| `REPO` / `BRANCH` | 默认本项目仓库的 `main` 分支 |

脚本是**幂等**的:重复执行不会重复下载 Node、不会覆盖已有 `.env` 的其他配置。

脚本实际做了什么(旧版做不到的部分已补齐):

1. 装基础依赖;
2. 装 Node 并**校验 SHA-256**;
3. 创建低权限用户 `itodo`,主服务**不再以 root 运行**;
4. 拉代码 + `npm install --omit=dev --ignore-scripts`(跳过 Electron,服务器不需要);
5. 生成 `chmod 600` 的 `.env`(含随机 OneBot 令牌);
6. 从 `deploy/systemd/` 安装 `msg2todo.service` + **`msg2todo-backup.timer`(每日 03:00 备份)**;
7. 可选:装 NapCat;
8. 可选:装 Caddy 并配置域名反代。

## 三、装 QQ 机器人(可选但推荐)

**脚本能装的那部分**:下载并解压 `NapCat.Shell.zip` 到 `/opt/QQ-napcat/.../napcat`,并安装 `napcat.service`。

**仍需手工做的部分**(NapCat 本身的特性,无法完全脚本化):

```bash
# 1) 复制官方 QQ 客户端到 /opt/QQ-napcat(按 README「QQ 接入(OneBot v11)」)
# 2) 写 loadNapCat.js 并修改 /opt/QQ-napcat/package.json 的 main 字段
# 3) 配置反向 WS → ws://127.0.0.1:3001(令牌填 .env 里的 ONE_BOT_ACCESS_TOKEN)
#    cat /opt/msg2todo/.env | grep ONE_BOT_ACCESS_TOKEN
# 4) 启动
systemctl start napcat
```

首次启动控制台会打印二维码(也会生成到
`/opt/QQ-napcat/resources/app/app_launcher/napcat/cache/qrcode.png`),用 QQ 小号扫码。

> ⚠️ NapCat 版本会变。脚本默认 `NC_VERSION=v4.18.33`,若该版本已下架,去
> [NapCatQQ Releases](https://github.com/NapNeko/NapCatQQ/releases) 查最新 tag,用
> `NC_VERSION=vX.Y.Z` 重跑。
>
> ⚠️ 旧文档里那个 `QQ_3.2.13_..._amd64_01.deb` 下载地址**已 404**,不要再照它做。

## 四、迁移本地数据

```bash
# 本地电脑执行:
scp data/todos.db root@<服务器IP>:/opt/msg2todo/data/

# 服务器上修正属主并重启(主服务以 itodo 身份运行)
chown itodo:itodo /opt/msg2todo/data/todos.db*
systemctl restart msg2todo
```

## 五、HTTPS(强烈建议,Web Push 的前置条件)

**没有 HTTPS,`Web Push` 根本不可用**——这是当前线上一直没验证过的部分。

```bash
# 前提:域名已解析到本机公网 IP + 安全组放行 80/443
# 部署时带 DOMAIN= 即可自动完成;也可事后手工:
sed 's|112358wang\.xyz|你的域名.com|g' /opt/msg2todo/deploy/caddy/Caddyfile > /etc/caddy/Caddyfile
systemctl reload caddy
curl -I https://你的域名.com/     # 期望 200 + 有效证书
```

Caddy 配置里已经处理了两个容易踩的点:

- `/api/events` 的 **SSE 关闭了缓冲**(`flush_interval -1`),否则事件会被攒住不下发;
- `/app.apk` 与 `/api/app/update` 单独走 **不缓存**,避免 App 更新拿到旧版本清单。

## 六、重新打包手机 App(内置云地址)

在本地开发机执行:

```bash
git pull
SERVER=https://你的域名.com bash scripts/build-apk.sh
```

- `dist/msg2todo-安卓.apk` 即成品;
- 把 `public/app.apk` 与 `public/app-version.json` **一起**传到服务器(缺一不可,否则 App 会弹更新却 404);
- iPhone 用 Safari 打开域名 → 添加到主屏幕。

> ⚠️ **签名密钥只在开发机**:`android/itodo-release.jks` + `android/keystore.properties` 被
> `.gitignore` 排除,新克隆的仓库构建出来的是**未签名**包,既装不上也无法覆盖升级。
> 请务必单独备份这两个文件,并考虑放进 CI Secrets(见分析文档「阶段 3」)。

## 安全建议

- ✅ **务必设置 `WEB_AUTH_TOKEN`**:留空时(旧默认)所有请求按管理员放行,数据等于对公网裸奔;
- ✅ SSH 改公钥登录:`PasswordAuthentication no`;
- ✅ 安全组只放行 **22(限常用 IP)/ 80 / 443**;
- ✅ **不要**在公网直接开放 8080 / 3001:主服务应监听 `127.0.0.1`,由 Caddy 反代;
  学生的个人机器人用 `wss://<域名>/onebot`;
- ✅ `.env` 权限 600、属主 `itodo`,**永不入库**;
- ✅ 定期确认备份真的在跑:`systemctl list-timers msg2todo-backup.timer`;
- ✅ 定期轮换令牌,尤其是任何曾经写进过仓库/文档的。

## 常见问题

| 问题 | 解决 |
|------|------|
| 手机打不开看板 | `systemctl status msg2todo`;确认安全组放行对应端口(Caddy 反代时是 443,不是 8080) |
| 服务起不来 | `journalctl -u msg2todo -n 50 --no-pager` |
| QQ 机器人连不上 | NapCat 反向 WS 填 `ws://127.0.0.1:3001`;`journalctl -u msg2todo \| grep 'self_id'` 应看到「登录成功」 |
| 证书签不下来 | 域名必须已解析到本机公网 IP;80/443 必须放行;`journalctl -u caddy -n 50` |
| App 弹更新但下载失败 | `public/app.apk` 没传上去(被 `.gitignore` 排除,必须手工 scp) |
| 更新后服务没重启 | 现已修复:`scripts/update.sh` 用系统级 `systemctl`(旧版误用 `--user`,永远不生效) |
| 备份失败 | `journalctl -u msg2todo-backup`;注意 NAS/磁盘满与属主问题 |
